# UELink 更新日志

格式说明见仓库根目录的 `docs/changelog.md`（`scripts/check.mjs` 和发布流程依赖这个格式）。

## v2.16.0

> 云端编不了 UE，这一版还没在本地用 UE 完整编译验证过，编译有问题请反馈。

### 新功能
- **导入外部文件** — 把磁盘上的 FBX、贴图、音频等导入成资源，可以一次导入多个、先演练看会生成哪些资源、已有的要明确写覆盖才覆盖；不弹导入选项对话框，也不自动保存
- **重新导入** — 按资源记下的源文件重新导入，能一次处理一批
- **调编辑器函数库** — 能列出和调用编辑器函数库里蓝图能调的静态函数（比如静态网格的 LOD、碰撞设置），每次调用包进编辑器事务可以撤回，能一次对一批资源调

### 新功能
- **按名字通配符选资源** — 资源搜索可以写 `*_Boss`、`BP_Enemy*` 这样的名字模式，也能写要排除的模式；批量操作按条件选一批蓝图时，Agent 不用再把几百个资源名逐个列出来

- **批量操作不限个数** — 一次批量不再限 2000 个资源；资源搜索 `limit` 写 0 时不截断，Agent 按条件选一大批时一次做完

### 改进
- **按 C++ 父类选蓝图认整条继承链** — 以前只认蓝图最近的那个 C++ 父类（继承 Character 的蓝图写 Pawn 选不中），现在写 Pawn、Actor 这类更上层的 C++ 类也能选中

## v2.14.0

> 云端编不了 UE，这一版还没在本地用 UE 完整编译验证过，编译有问题请反馈。

### 新功能
- **批量操作** — 蓝图修改、读大纲、读图、编译、改属性、复制、改名、删除等操作可以一次传入多个资源（最多 2000 个），同一组修改逐个套用；改之前先整批演练，全部通过才真改，中途失败默认把这批已经改好的撤回；结果按资源汇总
- **按父类和标签找资源** — 资源搜索可以按蓝图父类（含间接继承）和资源注册表标签筛选，不用加载资源
- **一条蓝图操作改多个组件** — 改组件、删组件、改删变量和函数时名字可以给多个、写通配符，组件还能按类选（比如全部静态网格组件），不用每个组件写一条
- **一条操作改多个属性、按条件改** — 改组件和类默认值时一条可以改多个属性；可以写「当前值是 A 才改」，对不上的跳过；改属性的结果和演练都带改前改后的值
- **DataTable 一次改多行** — 按行名列表、通配符或别的列的值挑行，同一列一次改完，能演练、能撤回
- **按类和标签找关卡里的 Actor** — 批量改一类 Actor 时用
- **蓝图修改「没有才加」** — 加变量、函数、组件、接口时可以标「已经有了就跳过」，同一组修改重复执行不会因为已存在而失败
- **资源版本差异** — 能把某一版资源文件（或编辑器里还没保存的那份）读成结构化的快照：组件、类默认值、变量、蓝图节点和连线、数据表的行，Agent 面板资源页的「版本差异」按它逐项比较哪一版改了什么

### 改进
- **作业的步数上限** — 一个作业最多 2000 步（原来 500）

## v2.11.0

> 云端编不了 UE，这一版还没在本地用 UE 完整编译验证过，编译有问题请反馈。新加的几类 trace 数据（内存标签、内存分配、加载、文件、任务、线程切换、网络、区域、会话信息）各有一个开关（`UELinkCompat.h` 的 `UELINK_TRACE_*`），哪一类编不过可以先关掉它，其余照常用。

### 新功能
- **Agent 能读到 trace 里的全部数据** — 面板的 Agent 分析 trace 时，除了计时器、帧、计数器，还能读每帧各线程忙了多久、卡顿帧比平时多出来的时间花在哪、渲染帧、会话信息（平台、构建配置、命令行）、区域、LLM 内存标签、内存分配（按标签 / 调用栈聚合，查泄漏）、包加载、文件读写、任务等待、线程切换、网络收发
- **计数器一次给统计** — 列计数器时可以顺便给每条的平均、最大、首尾值，不用一条条取走势才知道哪个在涨

### 改进
- **分析 trace 不再卡编辑器** — trace 查询挪到后台线程算，编辑器里只做登记；同时最多算 4 个、多的排队，几个 Agent 一起查也不会把编辑器拖慢；单次查询最多 20 秒，超了返回已经算出的部分并说明怎么缩小范围
- **被测的游戏进程不受影响** — 这些分析都在编辑器或后台编辑器里做，游戏进程里没有新增任何常驻开销

## v2.9.0

> 云端编不了 UE，这一版还没在本地用 UE 完整编译验证过，编译有问题请反馈。

### 新功能
- **Lua 函数进 Unreal Insights trace** — 录 trace 时带上 `lua` 通道（`luac` 让 C 函数也单独成块），每个 Lua 函数就是时间轴上一块，和 UE 的作用域嵌在一起：哪一帧慢、慢在哪个 Lua 函数、是从哪个 UE 回调进来的一眼能看出；同一份文件用 UE 自带的 Unreal Insights 打开也能看到。计时器带 .lua 文件和行号，每帧另有 `Lua/FrameMs`、`Lua/Calls`、`Lua/MemoryKB` 三个计数器。没在录制、或没开 `lua` 通道时没有任何开销。`trace.query` 加 `luainfo`、`tree`（火焰图用的调用树），`timers` 加 `lua`、`mergeC`（见协议文档）

### 改进
- **Lua 性能采样的函数名不再是 ?** — UnLua 从 C++ 调进来的函数（`ReceiveTick` 这类）按模块表里的字段名认出来，显示成 `模块:函数`；C 函数显示成 `UE.接口名` 或 `lua.string.format`
