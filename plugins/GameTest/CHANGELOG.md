# GameTest 更新日志

格式说明见仓库根目录的 `docs/changelog.md`（`scripts/check.mjs` 和发布流程依赖这个格式）。

## v2.3.0

> 还没在本地用 UE 完整编译验证过（云端编不了 UE），编译有问题请反馈。

### 新功能
- **执行 GM 的步骤** — 新动作 `gm.run`：执行 Agent 面板里的一条 GM（预设、自定义 GM、宏），面板把它展开成步骤一起存进脚本，参数在里面按 `$参数名` 用
- **接口 `Gm.Run`、`Gm.Lua`** — 测试里执行 C++ GM、Lua GM，和面板 GM 页点一下走同一条路
- **附带 GM** — 每一步都能挂「执行前 / 成功后 / 失败时」要跑的 GM（`hooks`），可以排序、只在循环第一次跑；出错默认只记一笔不算失败，也可以设成让这一步失败；成功后和失败时那组能用 `$ret` 拿到这一步的返回值

### 改进
- **只记一笔的出错** — 报告里这类记录标 `warn`，运行中推送的状态是 `warned`，整次运行照样算通过，面板标黄显示

## v2.1.0

> 还没在本地用 UE 完整编译验证过（云端编不了 UE），编译有问题请反馈。这一版改了脚本格式：只认 schemaVersion 5，旧脚本不再迁移，要按新写法重写。

### 新功能
- **新的属性路径写法** — 属性路径每段一个符号：`@.ShopId`（自己的属性）、`@/Header/TxtTitle:text`（子控件的状态）、`@#shopName`（Lua 字段）、`@item.Data.ItemId`（列表条目的数据）、`@.GetLevel()`（无参取值函数）；旧写法会报错并告诉你新写法怎么写
- **按 Lua 类找对象** — 对象引用的类可以写 `lua:模块名`，找绑了这个 Lua 模块（或它的子类）的对象；`in` 可以写 `lua`，也可以同时选几处（`["screen", "lua"]`）
- **类树** — 新操作 `gt.classes` 列出 UE 类和 Lua 类的继承树，带实例数，蓝图类不用加载资产
- **单步带对象** — `gt.step` 可以带 `objects`（名字 → 对象引用或 `@pawn` 这样的来源），步骤里直接写名字或 `{"$obj": 名字}`
- **对每个对象都调** — `obj.call` 加 `each: true`：引用命中几个就每个都调一遍，返回值和调用记录都是数组
- **函数参数的对象类型** — `gt.vars` 列函数参数时，对象参数带上它要的类（`objectClass`）
- **属性带 UE 分类** — 属性树的每个属性带上它在 UE 细节面板里的分类（行为、外观、内容……），面板照 UE 的样子分组显示

### 改进
- **组名改成「属性」** — 对象本身的属性组不再叫「自己」
- **对象名字可以用中文** — 场景 `objects` 里的名字可以用中文；值也可以直接写 `@pawn` 这样的来源

### 移除
- **不再迁移旧脚本** — 只认 schemaVersion 5，其他版本报「旧格式不再支持，请按新写法重写」

## v2.0.0

> 还没在本地用 UE 完整编译验证过：云端编不了 UE，这一版改动很大（对象引用整套重写），C++ 和自动化测试都没在本地跑过，编译有问题请反馈。需要 UELink 2.12.0 起。场景格式升到 `schemaVersion: 4`，旧场景要先在 Agent 面板里点「升级脚本」。

### 新功能
- **对象引用 = 类 + 唯一标识** — 定位、判断、操作对象统一写成 `{class, in?, ident?, many?, near?}`：按类收候选，按 `ident`（属性 + 比较）挑出那一个，条目写成「容器里的某个条目」。场景的 `objects` 给引用起名字，步骤里直接写名字。写法见 `docs/game-test-ref.md`
- **部件写法** — 点按钮、拖动、输入文字等写 `{"obj": 引用, "part": "BtnBuy"}`，部件名就是 WBP 里的控件名，嵌套用 `.` 连
- **对象判断** — 条件写 `{obj, prop, op, value}`：`prop` 可以是反射属性（`@self.Gold`）、部件属性（`@BtnBuy.IsEnabled`）或算出状态（`:onScreen`、`:shown`、`:text`、`:selected`…），`op` 按属性类型给（数值、文字、布尔、枚举、颜色、向量…）；表达式里用 `prop(引用, "路径")` 读
- **对象动作** — `obj.call`（调函数，原 `invoke`）、`obj.close`（按关界面规则关：返回键、CommonUI 停用、调函数、移除，关完核对）、`obj.find`、`obj.wait`、`obj.set`
- **新接口** — `gt.tree`（界面 / 世界里的对象树）、`gt.highlight`（在游戏里框出对象）、`gt.props`（一个对象能拿来当标识和判断的属性，带推荐分、可用的比较、同类里的取值）、`gt.refFor`（给选中的控件生成引用）；`gt.resolve` 能解析引用并在游戏里标出来
- **设置** — `identRules`（各类默认用哪些属性当标识）、`closeRules`（各类怎么关）、`refDefaults`、`allowDestroy`
- **深度检查认引用** — `gt.validate` 对照 WBP 控件树查部件名（`part_missing`）、对照类的反射查属性（`prop_missing`）、对照属性类型查比较（`op_type`）

### 改进
- **录制直接存成新写法** — 录到的点击、等待、断言保存时转成对象引用和部件写法，界面在 `objects` 里起好名字；拿不准标识的步骤标 `todo`，面板上补
- **控件状态** — 新增算出状态 `:selectedIndex`（下拉框）、`:selectedCount`（列表）、`:scrollOffset`（滚动框）、`:open`（菜单锚点）、`:selectedKey`（按键选择器）、`:activeIndex`（切换器）、`:expanded`（折叠区），旧场景的 `stateKey` 升级后落在这些名字上
- **部件名和属性路径里可以写变量** — `part`、`slate`、条件的 `prop` 里嵌 `$变量`（被 call 的子脚本按参数点不同的部件：`"part": "$nav"`）
- **守护和 skipIf 用对象判断** — 守护的 `when` 写对象判断，`do` 用 `obj.close`；`skipIf` 写 `{cond, also?, settleMs?, verify?}`
- **gt.keys / gt.actions 带新字段** — 字段条目带 `prop` 路径；动作清单带 `compares`、`states`、`closers`

### 注意
- **选择器字符串不再支持** — `WBP_X:Root/Btn`、`$item>BtnClaim` 这类写法报 `selector_removed`；按控件写的判断报 `cond_removed`；`text(sel)` 这类表达式函数报 `expr_removed`；`invoke`、`widget.close`、`widget.call`、`find` 报 `action_removed`。都在提示里写了改成什么，面板「升级脚本」会自动迁移

- **需要本地确认的引擎接口** — 下面这些是按印象写的签名，没在 5.4 / 5.8 上编过，编译报错先看这里（拿不准的都包在 `GameTestCompat.h` 里）：
  - `FTextInspector::GetNamespace` / `GetKey`（`GameTestCompat.h`）：按返回 `TOptional<FString>` 或 `FString` 写了两个重载接住；若是别的类型（如 `FTextKey`）要在 `TextPieceOf` 加一个重载
  - `UWidgetBlueprintGeneratedClass::GetWidgetTreeArchetype()`（`gt.props` 的类模式、深度检查）：假设返回 `UWidgetTree*`
  - `UWidgetTree::ForEachWidget` / `GetAllWidgets`、`UPanelWidget::GetChildAt`（对象树、部件查找）
  - `UCommonActivatableWidget::DeactivateWidget` / `IsActivated`（关界面的 CommonUI 规则，可选模块）
  - `UUserListEntryLibrary::GetOwningListView`、`UListView::GetSelectedItem` / `GetNumItems` / `ScrollIndexIntoView`、`UDynamicEntryBox::GetNumEntries`（条目引用、`:selected`、`:count`）
  - `UWidget::GetIsEnabled` / `GetVisibility` / `SetVisibility` / `GetCachedGeometry` / `RemoveFromParent`、`SWidget::IsHovered` / `HasAnyUserFocus`（算出状态、关界面）
  - `UImage::GetBrush`、`UTextBlock` / `URichTextBlock` / `UEditableText(Box)` 的 `GetText` / `SetText`、`UCheckBox::SetIsChecked` / `SetCheckedState`、`USlider` / `USpinBox` 的 `SetValue`（`obj.set`、`:text`、`:image`）

## v1.11.3

> 还没在本地用 UE 完整编译验证过，编译有问题请反馈。需要 UELink 2.12.0 起。

### 改进
- **循环次数 0 = 不限** — 循环的 `max` 写 0 或不写就是不限轮数，跑到条件成立或手动停止为止；写正数仍是上限（不再限制最多 1000）。不限时可以给循环块写总时限兜底
- **超时 0 = 不限** — 步骤或块的 `timeoutMs` 写 0 表示一直等、不超时（不写还是用默认值），卡住了可以在面板上停止
- **守护触发次数 0 = 不限** — 守护的 `max` 写 0 表示这次运行里触发几次都行（靠冷却时间隔开）

- **录制拖动、滚轮、打字** — 在控件上按住拖动录成 `drag`，滚轮录成 `wheel`（连着滚合成一条），在输入框里打的字录成 `type`，回车、退格这类键录成发给那个控件的 `key`
- **录制时拾取断言** — 按住 Ctrl+Alt 点一个控件，这次点击不传给游戏，录成一条「这个控件可见（文字是…）」的断言
- **`click` 真实点击并自动等待** — 先等控件出现、可见、可用、不再移动、没被别的东西挡住，再把光标移过去按下松开，并核对确实是这个控件接住了；等不到就说明卡在哪一条。默认最多等 10 秒（设置「UI 等待超时」）。旧的直接调用改成 `via: "code"`
- **新动作 `drag`、`wheel`，`type` 按真实键盘输入** — `type` 默认先全选再逐字输入（`append` 接着打），`key` 可以指定发给哪个控件
- **选择器能写到更多控件** — 列表条目（`列表[3]`、`列表[Id=5]`）、嵌套的 WBP（`外层>里层`）、没有 UMG 的 Slate 控件（`>>SButton[text=确定]`）、整个屏（`屏名:.`），屏名也可以写 WBP 资源路径
- **`gt.inspect` 查光标下的控件** — 返回命中路径、该写的选择器和核对结果、最近一次点击被谁接住；控制台命令 `GameTest.Inspect`

### 改进
- **UI 操作之间不再录等待** — 回放时 `click`、`type` 自己会等控件，录下来的秒数只会让慢机器失败、快机器白等；开始录制时打开 `keepPace` 可以照录

### 注意
- **场景格式升到 2** — 旧场景（格式 1）里的 `click`、`type` 读入时自动按 `via: "code"` 跑，行为不变；想换成真实点击，去掉 `via` 即可
- **打字录制需要 Slate 调试** — 没编 Slate 调试的进程（录制状态里 `handlerSource` 是 `hitPath`）按命中路径推断控件，打字录不到

### 新功能
- **录制回放** — 在游戏窗口里操作一遍，录成场景文件（场景根下的 `recorded/`），回放就是跑这份场景。点按钮录成「点哪个控件」而不是坐标，界面布局变了也能回放；改输入框、下拉框、滑条录最终值；点在游戏画面上和按键盘、手柄键录成真实按键，节奏用等待还原。录的时候可以插检查点（顺带截图），之后在面板里改成断言。用引擎公开的输入预处理器实现，不改引擎和项目代码
- **按键动作 `key`** — 按下、松开或点按一个键盘键、鼠标键，走和真实按键一样的输入路径，不需要知道项目的输入资产
- **在 Agent 面板里跑测试** — 场景列表、运行、逐步结果、截图、录制都在面板 UE 页的 GameTest 页；Agent 通过面板的 `ue_gametest` 工具用同一套操作。运行进度实时推到面板

### 改进
- **通信交给 UELink** — 去掉自己开的 HTTP 服务和端口设置（原来没有令牌，游戏进程里默认关着），操作挂在 UELink 的 `/rpc` 上（`gt.*`），共用令牌、只听本机；游戏进程里装了 UELink 就能用
- **CommonUI、GAS、EnhancedInput 拆成可选模块** — `stack.push/pop`、`ability.input`、`input.start/stop` 搬进各自的模块，主模块不再依赖这几个插件；动作清单里会标出哪些动作因为缺插件不可用，写了这些动作的场景会提示要开哪个插件
- **动作登记表** — 动作的说明、参数和实现在一处登记，不会再出现「清单里有、实现里没有」
- **返回内容有上限** — 快照、报告超过 12000 字时写进 `Saved/GameTest/responses/`，只返回路径，不撑爆 Agent 的上下文
- **场景可以自带步间隔** — 场景文件写 `stepDelayMs` 时覆盖项目设置（录制的场景写 0）
- **去掉原项目的名字** — 控制台命令改成 `GameTest.Step / Health / Actions`，测试名改成 `GameTest.*`，场景目录跟着项目的文档走（项目外层同级有 `ProjectDoc/docs` 就放 `ProjectDoc/docs/GameTest`，否则放项目里的 `docs/GameTest`，也可以在项目设置里指定）；测试探针只用插件自带的 C++ 类，不引用项目资产
