# 更新日志的写法

每个插件在自己的目录里有一份 `CHANGELOG.md`（`plugins/<插件>/CHANGELOG.md`），`scripts/check.mjs` 和发布流程依赖这个格式：

- 每个版本一节，标题为 `## vX.Y.Z`，最新的在最上面。合并到 `main` 时，CI 读每个插件最上面一节：标签 `<插件>-v<版本>` 还没有，就打包并发布 Release。
- 改了 `plugins/<插件>/` 就在它的 CHANGELOG 最上面加新版本节，同时改 `.uplugin` 的 `VersionName`、`Version`（加 1）和版本宏（`kit.json` 的 `versionHeader` 指向的那个）。
- 节内用 `### 新功能`、`### 改进`、`### Bug 修复`、`### 注意`，条目写成 `- **短标题** — 说明`，写用户能感受到的变化。
- Release 说明会在这一节后面自动附上「上一版以来改了这个插件目录的提交」（标题以 `内部：` 开头的跳过），所以提交标题也要写清楚改了什么。
- 每次更新用户都要在本地重新编译插件，所以攒一批改动再发版。
- 直接发正式版，不发预发布（客户端默认只装正式版，预发布用户拿不到）。还没在本地用 UE 完整编译验证过的版本，在这一节开头写一句说明。
